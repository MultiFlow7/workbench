议题 B · req-027 子功能1

P2 对话树节点 Token 标注显示模式

对话树中每个节点需要显示 token 消耗数据，三种显示策略的权衡在于信息密度与视觉噪音的平衡。

B1 始终显示 token 小徽章 推荐
对话树

0001-002 ↑2.1k ↓0.8k
0001-003 ↑5.2k ↓1.1k ⚠
0001-004 ↑1.8k ↓0.5k
每个节点旁常驻显示「↑ input ↓ output」小徽章，高消耗节点加 ⚠ 标记。信息始终可见，无需交互。
优点
  • 不需要悬停即可扫视全树
  • 快速识别高消耗节点
  • 实现简单
缺点
  • 节点行内容变多，树更宽
  • 不关注 token 的场景有噪音

P2 顶部工具栏新增「Token」开关按钮，点击切换显示/隐藏 token 徽章。默认关闭，用户主动开启。

  • 默认视图不受影响

  • 增加了一个工具栏按钮
  • 状态存储和切换逻辑复杂度略增
  • 高消耗节点无被动警示
建议 B1（始终显示）：v0.3 是 token 可见性的第一个版本，应该让用户自然建立「对话树有 token 数据」的认知。始终显示的小徽章噪音很低（7px 字体），但可以被动感知高消耗节点。如果后续发现确实影响使用体验，v0.4 可以改为 B3（开关）。
