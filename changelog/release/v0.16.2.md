# 工作台 v0.16.2 · Conversation Hierarchy

## 概述

v0.16.2 是 req-067 的结构补丁：把工作台从隐式 `Project -> QAAtom tree` 升级为显式 `Project / Unprojected -> Conversation(Canvas Group) -> Start Point -> QAAtom tree`。

本版本不重写外部导入器、不批量迁移旧 Vault、不改变 QA atom Markdown 主格式。它只把“对话 / 会话”提升为正式结构层，让后续 Codex / Claude 等外部对话迁移能保留项目归属、会话边界和来源元信息。

## 已交付

- 新增 `ConversationMeta` 与 `Conversations/` Vault 索引目录。
- 新增 conversation IPC：列表、创建、更新、追加 atom、关联 project。
- Project 索引兼容混合读取：`[[conv-xxx]]` 作为新 conversation id，旧 atom wikilink 作为 legacy atom id。
- 新 `Project` 收窄为 folder-bound 项目：创建项目时必须选择本地文件夹，项目文件写入 `folderPath`。
- 旧 `Projects/*.md` 不再作为新 Project 参与产品语义，而是作为无项目对话里的完整历史画布保留。
- 老 Vault 的 project atom index 会按旧画布整体生成无项目 legacy canvas conversation；未索引 root atom 会合并生成“无项目旧画布”，不需要破坏性迁移。
- 新建对话先写 draft conversation，第一轮发送后转为 active 并绑定 root atom。
- P1 改为项目下的对话 / 无项目对话两段分组；P2 保留无限画布，进入 conversation 后 BranchTree 显示该 conversation 的共享画布，多个 root 起点由用户选择。
- conversation 行可展开显示共享画布里的 root 起点；点击起点进入同一画布并选中对应树。
- P3 保持 root -> 当前节点线性历史，但路径回溯在当前 conversation 边界内停止。
- P4 在未选 atom 但已选 conversation 时显示 conversation 元信息。
- `workbench` package 版本升至 `0.16.2`。

## 兼容性

- 不改变现有 QA atom 文件格式。
- 保留 `add_atom_to_project` legacy IPC；新发送路径改为写入 conversation。
- 无 selected conversation 的底层 `selectAtom` 保留 legacy 全局 path 计算，用于兼容旧调用方；UI 正常入口不暴露跨 conversation QA 选择。
- 旧 Project 文件中的多个 root atom 默认保持在同一个无项目对话画布中，不自动拆成多条对话。
- 如果 QA / Projects 是同一父目录下的绝对路径，默认 `Conversations` 目录跟随落在同一父目录，避免老用户本地路径漂移。
