议题 D · 影响 Node 9

仪表盘图表库选择

req-028 时序折线图需要渲染多模型数据曲线。v0.3 明确「不引入图表库」使用 CSS 纯实现，v0.4 面临真正的时序可视化需求，是否引入 Recharts 是本版本的关键决策。

⚠ 背景张力：req-028 规格书明确建议使用 Recharts；v0.3 product.md 明确「不引入新的外部依赖，避免为简单统计引入 chart.js / recharts 等重量级库」。两者方向相反，需要在此决策中明确取舍。
D1 引入 Recharts

安装 recharts@2.x（约 430 KB gzip 后约 140 KB），使用 <LineChart> + <Line> 组件实现多模型时序折线图，原生支持动画、Tooltip、响应式缩放。

Recharts 渲染效果（含 Tooltip + Responsive）

+140 KB gzip npm install recharts 动画 + Tooltip

优点

  • 开发成本极低
  • Tooltip、动画开箱即用
  • v0.5 扩展图表类型无需重写
  • req-028 原意推荐

代价

  • 打破 v0.3「零依赖」原则
  • 包体积增加约 140 KB
  • Tauri 桌面 app 影响可接受
D2 CSS+SVG 手写折线 technical.md 默认

使用原生 SVG <path> 绘制折线，不引入任何图表库。实现 200 行内，支持多模型折线、X/Y 轴、图例，无 Tooltip 动画。v0.4 数据量（<1000 节点）下性能充足。

SVG 手写实现（无动画，无 Tooltip，简洁）

零新依赖 与 v0.3 原则一致 无 Tooltip

优点

  • 零新依赖
  • 与 v0.3 零依赖原则一致
  • 代码完全可控
  • 打包体积不变

代价

  • 无 Tooltip 交互
  • 需自行实现聚合逻辑
  • v0.5 扩展需更多工作量
D3 仅卡片，不做折线图

v0.4 只实现四张汇总卡片和按模型的 CSS 条形图（延续 v0.3 风格），不做时序折线图。时序图推入 v0.5，届时结合 llm_calls 真实数据一起实现。

议题 E · 影响 Node 7

Token 数据聚合位置

req-028 仪表盘需要扫描所有 QA atom 的 frontmatter 并按日期 + 模型聚合。这可以在前端 JS 完成，也可以在 Rust 后端的新命令中完成。两种方案的代码量相当，主要差异在于未来扩展方向。

req-028 规格书原文：「前端或 Rust 后端计算（v0.4 视数据量决定）」。technical.md 以 E1（前端 JS）为默认实现，E2 为替代方案，实现时切换即可，DashboardView 无需改动。
E1 前端 JS 直接聚合 technical.md 默认

前端在 atomAggregation.ts 中对 store 中已有的 atom 列表直接做 O(n) 遍历，按日期+模型分桶，在 React useMemo 中完成。无需新增 Tauri 命令，无需后端改动。

// 前端聚合（tokenAggregation.ts） const stats = useMemo( () => aggregateAtoms(filteredAtoms), [filteredAtoms] ) // atoms 已在 store 中，无需额外 IPC 调用

v0.4 阶段对话节点数量 <500，O(n) 计算在浏览器主线程上完成时间 <5ms，无感知延迟。

无新 Tauri 命令 无额外 IPC 开销 后端无感知变更

优点

  • 不需要新后端命令
  • 响应速度最快（纯内存）
  • v0.5 切换 llm_calls 数据源时只改前端
  • 代码完全在前端可调试

代价

  • atom 数量超过 2000 时需考虑 Web Worker
  • 扫描范围仅限已加载到 store 的 atom
  • （v0.4 阶段两者均可接受）
E2 Rust 后端 get_token_stats 命令

在 Tauri Rust 侧新增命令 get_token_stats({ project_path, date_from?, date_to? })，扫描磁盘上的 atom 文件 frontmatter，聚合后返回 DayModelBucket[] JSON，前端直接使用。

// Rust 命令（commands/token_stats.rs） #[tauri::command] async fn get_token_stats( project_path: String, date_from: Option<String>, date_to: Option<String>, ) -> Result<Vec<DayModelBucket>> { ... } // 前端调用 const buckets = await invoke('get_token_stats', { projectPath: currentProjectPath, dateFrom: cutoffDate, })

适合未来扩展：v0.5 接入 llm_calls SQLite 表后，直接在 Rust 侧合并两个数据源，前端接口不变。

新 Tauri 命令 扩展性更好 +200 行 Rust 代码

优点

  • 可扫描全量磁盘文件（不受 store 限制）
  • v0.5 切换 llm_calls 只改 Rust 不改前端
  • 可添加日期范围索引优化大数据量

代价

  • 需要新增 Rust Tauri 命令
  • IPC 序列化/反序列化开销
  • v0.4 阶段优势不明显
