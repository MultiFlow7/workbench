# req-016 · 多层级任务可视化

## 需求描述

可视化是贯穿工作台所有维度的 human-first 交互层。用户应当能从不同入口、不同层级的视角管理 AI 团队的工作状态，而不是在命令行日志里找信息。

## 三个视角层级

### 1. 项目视角
- 所有项目的版本流水线状态
- 每个版本：product 规划 → technical 审查 → 工程实现 → 验收
- 当前卡点高亮：「v0.2 product.md 等待你选需求范围」

### 2. 当前状态视角（跨项目总览）
- 所有正在运行的 Agent 任务（类似 GitLab CI pipeline 总览）
- 按状态分组：运行中 / 等待决策 / 已完成 / 失败
- 每个任务：角色 + 任务摘要 + 耗时 + 当前步骤

### 3. Agent 平面视角
- 进入某个具体 Agent 任务的详情
- 看到该 Agent 的执行流（见 req-017）
- 可以直接向该 Agent 发送指令或修正方向

## 交互要求

- 三个视角之间可自由切换，不丢失当前主对话状态
- 新任务、状态变更、决策请求有非侵入式通知（不打断主对话）
- 可以从任意视角快速跳转到「决策收件箱」（req-018）

## 讨论记录

**2026-05-18**：用户明确「可视化应贯穿始终所有维度」，不是单一功能而是整体设计语言。命令行里的思考流输出是原始形态，需要演化为结构化的多层级 UI。不同入口看到不同粒度的逻辑。
