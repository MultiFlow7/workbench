# req-018 · 决策收件箱

## 需求描述

当后台 Agent 需要用户拍板时（scope 变更、风险决策、需求范围选择），不打断主对话，而是将决策请求积累在「收件箱」中，用户在方便时处理。

## 决策项结构

每条决策请求包含：
- **来源**：哪个 Agent / 哪个任务触发的
- **问题**：需要用户决策的具体问题
- **选项**：预定义的选项（如「纳入当前版本 / 推入 backlog / 放弃」）
- **风险等级**：低（建议）/ 中（影响当前版本）/ 高（数据风险 / 范围重大变更）
- **等待时长**：这个决策已经 pending 多久了
- **影响说明**：如果继续等待，哪些任务会被阻塞

## 交互行为

- 主对话界面有非侵入式角标提示（「3 个待决策项」）
- 用户可以随时打开收件箱，批量处理或逐一处理
- 高风险决策可以配置为「立即推送通知」（更显眼的提示）
- 用户做出决策后，相关任务自动从 `awaiting-decision` 恢复执行

## 与主对话的关系

主对话（用户 ↔ CEO）是最高优先级频道，收件箱决策不进入主对话线程，是独立的管理界面。用户说「帮我看看有什么待决策的」才会在主对话里汇报。

## 讨论记录

**2026-05-18**：用户希望工程任务链路在后台运行，主对话专注于新需求讨论。决策收件箱是实现「主对话不被打断」的关键机制——把决策需求从对话流中剥离出来，做成异步队列。
