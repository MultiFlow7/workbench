# req-020 · 主对话保护

## 需求描述

主对话（用户 ↔ CEO Agent）是用户与工作台沟通的主频道，始终保持干净和专注。后台 Agent 的运行、输出、状态变更不进入主对话流，通过独立 UI 区域呈现。

## 具体要求

- 后台任务完成不会自动在主对话里发消息，只在独立通知区域提示
- 主对话的 CEO Agent 上下文不包含后台任务的详细执行日志（只包含任务状态摘要）
- 用户可以主动问 CEO「现在有什么在跑 / 什么需要我决策」，CEO 才汇报
- 新需求讨论、产品方向探讨发生在主对话，不被任何后台任务打断

## CEO Agent 的双模式

CEO 在两种上下文下被调用：
1. **主对话模式**：用户发消息 → CEO 响应，上下文 = 用户消息 + 项目状态摘要
2. **事件响应模式**：后台任务完成 / 决策请求 → CEO 处理，上下文 = 任务输出 + 当前状态

两种模式使用同一个 CEO Agent，但上下文不同，产出写到不同地方（主对话 vs 状态机 + 收件箱）。

## 讨论记录

**2026-05-18**：用户明确希望「可以不断地沟通新的需求」而不受工程任务干扰。主对话保护是实现「人管理 AI 而不是 AI 管理人的注意力」的基础。
