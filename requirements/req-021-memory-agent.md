# req-021 · 记忆 Agent

## 需求描述

专门负责维护和检索语义记忆的 Agent，为其他 Agent 调用提供「过去发生了什么、为什么这样决策」的上下文补充。与状态机（req-013）的结构化状态互补：状态机存「是什么」，记忆 Agent 存「为什么」。

## 两种持久化的区分

| | 状态机（req-013） | 记忆 Agent |
|--|--|--|
| 存储内容 | 任务状态、进度、产出物路径 | 决策原因、经验教训、项目背景 |
| 实现方式 | 后端确定性代码（Rust/DB） | LLM 维护的语义索引 |
| 检索方式 | 结构化查询 | 语义相似性检索 |
| 更新时机 | 任务状态变更时自动写入 | Agent 完成时主动提炼并写入 |

## 核心能力

- **记忆写入**：每次重要决策/经验发生后，提炼为记忆条目存入知识库（Obsidian .md 文件）
- **记忆检索**：其他 Agent 调用时，上下文构建器（req-015）向记忆 Agent 查询相关历史，注入为 context 第 5 层
- **记忆老化**：过时的记忆降低权重（如已废弃的设计决策）

## 与当前 Claude 记忆系统的关系

当前已有 `/Users/<name>/.claude/projects/.../memory/` 形态的文件记忆系统，是记忆 Agent 的 v0 版本。记忆 Agent 是这个系统的升级：加入语义检索、主动提炼、跨 Agent 共享。

## 版本规划

此需求计划在 CEO / 状态机 / 多 Agent 调度基础建好后实施，属于后期版本。v0.x 阶段用文件直接注入替代。

## 讨论记录

**2026-05-18**：用户明确将记忆共享和状态共享拆分为两个独立机制：「记忆共享靠上下文传递，这件事我会单独做记忆 Agent 来处理；状态共享靠后端确定性代码」。记忆 Agent 是独立的专项工作，不混入当前状态机设计。
