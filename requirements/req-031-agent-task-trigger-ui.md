# req-031 · Agent 任务手动触发 UI

## 需求描述

在控制台模式（P3）中，新增「触发任务」入口。用户可以选择 Agent 角色、填写任务描述（上下文 prompt）、指定所属项目和版本，提交后在 req-013 状态机中创建新任务记录。

这是「管得了」的最小实现——用户不依赖命令行就能启动 Agent 任务，工作台 UI 成为 Agent 调度的控制入口。

## 功能详述

### 触发入口

控制台模式 P3 顶部固定一个「+ 触发任务」按钮。点击后展开任务配置表单（可以是侧滑抽屉或行内展开，设计决定）。

### 任务配置表单

| 字段 | 说明 | 类型 |
|------|------|------|
| 执行角色 | 从已注册 Agent 列表中选择（对应 req-030 数据源） | 下拉选择 |
| 任务描述 | 自由文本，作为 Agent 的初始 prompt / 上下文 | 多行文本 |
| 所属项目 | 从当前已知项目列表选择（可选，默认「工作台」） | 下拉选择 |
| 所属版本 | 自由输入（如 v0.6）或从已知版本中选择（可选） | 输入或下拉 |
| 优先级 | low / medium / high（默认 medium） | 单选 |

### 提交行为

- 提交后调用状态机 API（`POST /tasks`），创建 `status=pending` 的新任务记录
- 任务立即出现在任务总览（req-016 数据源）中，用户看到任务进入队列
- v0.6 阶段：创建记录即完成，实际 Agent 执行需要人工或外部触发（后台执行能力是 req-014，推 v0.7）
- v0.6 UI 明确标注「任务已加入队列」，不暗示任务已开始执行

### 取消与重置

- 表单未提交时可随时取消，不产生副作用
- 提交成功后表单重置，不自动关闭（方便连续触发多个任务）

## 交互要求

- 触发表单不覆盖任务总览视图，用户可以在触发后立即看到新任务出现在列表中
- 表单字段校验：执行角色和任务描述为必填，不满足时禁用提交按钮
- 提交中状态：按钮显示 Loading，防止重复提交

## 验收标准

- 控制台模式 P3 显示「+ 触发任务」按钮
- 点击 → 表单展开 → 选择角色「workbench-product」→ 填写描述 → 点击「提交」→ 任务出现在任务总览列表（status=pending）
- 必填字段为空时，「提交」按钮禁用
- 任务提交后，任务总览列表（req-016）无需刷新即可看到新任务（状态推送实时更新）

## 讨论记录

**2026-05-19**：CEO 调度指令。v0.6 的手动触发只需要「创建任务记录」，不需要实际驱动 Agent 执行（那是 req-014 的职责范围）。这个功能让 UI 和状态机形成闭环——用户可以在工作台里看到和创建任务，为 v0.7 的真实调度打好数据通道。
