# req-050 · 切换对话时流式内容泄漏 + 强制跳转 bug 修复

## 背景与问题描述

存在两个相关联的 bug，均与流式生成过程中切换对话节点有关。

### 问题 A：流式内容泄漏

**场景**：C 节点正在 AI 流式生成，用户切换到 B 节点查看其他内容。

**表现**：C 节点的流式文字会出现在 B 节点的对话视图里，两个对话的内容混在一起。

### 问题 B：强制跳转

**场景**：C 节点 AI 生成完成时，用户正在查看 B 或其他任意节点。

**表现**：用户被强制导航到 C 节点，无论当时在查看什么内容，用户焦点被打断。

## 根因分析

- **泄漏根因**：`ai-token` 事件没有携带 `atom_id` 字段，ChatView 收到 token 后无法判断这条流属于哪个节点，直接写入当前视图的 streaming 状态。
- **强制跳转根因**：`ai-done` 事件处理的最后一行无条件调用 `selectAtom(atom_id)`，不管用户当前焦点在哪里。

## 修复方案

- `ai-token` 事件增加 `atom_id` 字段，ChatView 收到 token 时比对当前选中节点，不匹配则丢弃
- `ai-done` 事件处理中删除 `selectAtom(atom_id)` 调用（或改为仅在用户当前就在该节点时才执行）

## 与 req-051 的关系

req-051（并发对话）依赖本需求的基础修复。`ai-token` 增加 `atom_id` 是 req-051 多流并发的前提条件。建议先完成本需求再实现 req-051。

## 验收标准

- 在 C 节点流式生成过程中切换到 B 节点，B 节点不出现 C 的流式文字
- C 节点 AI 生成完成后，用户停留在当前节点，不被强制跳转
- C 节点生成完成的内容在 C 节点视图中正常显示
