为什么需要协作平面

你同时开着六个 Claude 对话窗口——工作台规划在这个 Tab，bug 排查在那个 Tab，技术文档在另一个窗口。你发现自己花了大量时间在窗口之间来回切换，试图记住"刚才那个节点讲到哪里了"，而不是在真正解决问题。

更深的问题是：你的每个 AI 对话都是孤岛。昨天这个 Agent 分析出来的结论，今天另一个 Agent 完全不知道。知识在对话里产生，也在对话里消失，没有任何沉淀。

界面痛点
多 AI 工具分散在不同窗口，对话历史和结构信息无法同时看到
管理痛点
AI 任务执行不透明，高风险操作没有审批机制，需要人工全程盯
协作痛点
AI 之间无法共享上下文，对话是孤岛，知识无法在 Agent 之间流动
能力痛点
AI 只能"说"，无法执行本地操作，人还是要手动转化每一个指令
产品

三种协作，一个平面

工作台的核心不是更好的聊天界面，而是让三种协作关系在同一个空间里同时运转。

01
🤝
人 ↔ AI
对话工作区
四面板布局让对话分支树（P2）和线性历史（P3）同时可见。点击任意节点，从根到该节点的完整上下文链路瞬间呈现，无需切窗口。
02
🔄
AI ↔ AI
Agent 协作网络
一个 Agent 的输出 Atom 成为另一个 Agent 的输入上下文。调度器自动接取任务、传递知识、推进任务链，AI 之间的协作不需要人工中转。
03
🎛️
人 管理 AI
执行控制台
Agent 注册表、任务状态机、Decision Inbox——所有 AI 的执行状态和高风险操作都汇聚在控制台，人保留完整控制权。
四面板职责分工
P1 · 导航
模式入口
切换三种工作模式（对话 / Agent 管理 / 控制台），浏览项目列表。不渲染结构，不渲染内容。
P2 · 结构
可视化结构
对话模式显示分支树；Agent 管理模式显示注册表；控制台显示服务状态。纯结构，不处理业务逻辑。
P3 · 主工作区
当前内容
线性对话视图、Agent 文档查看、任务总览与 Decision Inbox。P3 是人主要工作的地方，P2 选择节点，P3 响应内容。
P4 · 详情
上下文辅助
点击节点 / 任务后显示详情、元数据、关联 Atom。演化路径：只读详情 → 文档查看器 → 可编辑第二工作区。

存储层深度：信息库与思维粒子

传统数据库为人设计——行和列，SQL 查询，精确匹配。工作台的存储层从底层重新设计，让每一次对话以 AI 原生的形态沉淀下来：自包含、可关联、带语义环境的思维粒子，构成 Agent 之间流通的信息库。

传统数据库
📋数据被肢解成行和列，信息依赖外部拼装才有意义
🔍AI 需要 SQL 检索再组装，费力消化，高噪音
⏱不知道哪条数据过时，没有知识时效管理
🏝Agent 之间的知识是孤岛，无法直接传递
信息库 · 思维粒子 Atom
✦每个 Atom 自包含——背景、内容、关联关系一体，自我解释
🔗wikilink 动态关联，AI 拿到一个粒子就能沿链拽出相关上下文
📥Context Builder 直接把 Atom 注入上下文窗口，无需检索
🔄Agent A 的输出 Atom 直接成为 Agent B 的 file_refs 输入

差异化

核心创新

知识基底 · 信息库
AI 原生的知识底座——思维粒子 Atom
不是给旧仓库加语义索引，而是从数据的原子结构本身重塑。工作台里的每一次对话，产生的不是聊天记录，而是一个自包含的思维粒子——带有 ID、语义摘要、动态关联、前后文链接。
这是 AI 与 AI 协作的基础设施：Agent A 分析出的结论以 Atom 形式存入信息库，Agent B 通过 file_refs 直接拿到这个粒子注入自己的上下文，无需中转，无需重建。知识在 Agent 网络里自由流动。
思维粒子的四个特性
✦
自包含 — 背景、内容、关系一体，不依赖外部隐式知识，切片本身讲清一切
🔗
预关联 — wikilink 形成动态关联图，相关上下文不需要检索，沿链滑入
📥
直接注入 — Context Builder 把 Atom 文件推进上下文窗口，零检索开销
🔄
跨 Agent 流动 — 粒子在 Agent 间自由传递，知识不是孤岛
01
交互设计
双线对话视图
分支树（P2）和线性历史（P3）分离。P2 纯结构，P3 纯内容，点击节点联动切换完整上下文路径。线性对话的流畅感，加上分叉导航的灵活性，两者不互相干扰。
02
人机协作
非阻塞 Decision Inbox
AI 执行高风险操作时不强制打断当前工作——决策进入收件箱排队，按风险等级排序。人可以批量处理，批准后自动颁发 capability_token，Agent 从断点继续执行，工作流不中断。
03
执行层
四层 Context 注入调度
调度器不只是转发任务。Context Builder 为每个 Agent 构建完整认知包：角色提示 + 任务状态 + 信息库粒子（file_refs）+ 触发意图。Agent 以满上下文启动，不需要追问背景。
04
设计哲学
AI-first 后端 / Human-first 前端
后端以 Agent 自主执行能力为第一公民——状态机、并发控制、权限管控都服务于此。前端以降低认知负担为第一公民——四面板的每个职责边界，都在减少人切换上下文的次数。两者不冲突。
